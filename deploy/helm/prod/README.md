# Helm in production

Deploys Cryptomator Hub with bundled Keycloak and PostgreSQL from the published chart, exposed on two public hostnames with a TLS certificate from cert-manager. Passwords are generated by the chart and stored in Kubernetes Secrets.

Requirements:

- A Kubernetes ≥ 1.27 cluster with the **Traefik** ingress controller (bundled with K3s, for example) and a default StorageClass (one `ReadWriteOnce` volume for PostgreSQL). nginx works too, see [Routing variants](#routing-variants).
- DNS records for the two hostnames pointing at the ingress controller.
- [cert-manager](https://cert-manager.io/) with a `ClusterIssuer` — or an existing TLS secret, see [TLS variants](#tls-variants).
- `kubectl` and Helm 3.8+ (OCI support).

## Install

```bash
helm install hub oci://ghcr.io/cryptomator/charts/cryptomator-hub --version 2.0.0 \
  --namespace cryptomator --create-namespace \
  --set urls.hub.public=https://hub.example.com \
  --set urls.kc.public=https://kc.example.com \
  --set ingress.controller=traefik \
  --set ingress.certificate.clusterIssuer=letsencrypt
```

Helm prints the service names and the commands to retrieve the generated passwords. Wait until all pods are ready — Keycloak needs a minute on first start to import Hub's realm:

```bash
kubectl get pods -n cryptomator -w
```

Then retrieve the two admin passwords:

```bash
# Hub admin (realm user `admin`; the password must be changed on first login)
kubectl get secret -n cryptomator hub-secrets-hub -o jsonpath='{.data.hub_admin_password}' | base64 -d && echo
# Keycloak bootstrap admin (`admin`)
kubectl get secret -n cryptomator hub-secrets-kc -o jsonpath='{.data.kc_admin_password}' | base64 -d && echo
```

Open <https://hub.example.com>, sign in as `admin`, set a new password and enter your license (see <https://cryptomator.org/hub/>). Manage users and groups in Keycloak at <https://kc.example.com>; Hub syncs them every 5 minutes (`hub.config.keycloakSyncerPeriod`).

> [!IMPORTANT]
> Keycloak creates Hub's realm — including the redirect URIs derived from `urls.*.public` — only on its **first** start. Decide on the final hostnames before installing. Changing them later means editing the `cryptomatorhub` client in the Keycloak admin console (*Clients → cryptomatorhub → Valid redirect URIs*) in addition to `helm upgrade`.

### Routing variants

- **Two hostnames** (above): Keycloak and Hub live on different origins; the chart adds the Keycloak origin to Hub's `Content-Security-Policy` automatically.
- **One hostname with paths**: `urls.hub.public=https://example.com/hub` and `urls.kc.public=https://example.com/kc`. The chart adds a Traefik `stripPrefix` middleware per Ingress; a single-host certificate suffices.
- **nginx** instead of Traefik: `ingress.controller=nginx`. The chart then uses nginx's regex rewrite for path-based routing, and nginx redirects plain HTTP to HTTPS on its own once a certificate is attached.

### TLS variants

- **cert-manager** (above): `ingress.certificate.clusterIssuer=<name>`. One certificate covering both hosts is requested and stored in `hub-tls` (`ingress.certificate.secretName` to rename).
- **Existing certificate**: `ingress.certificate.secretName=<tls secret>` without a `clusterIssuer`. The secret must live in the release namespace and cover **both** hosts (wildcard / multi-SAN), or use the single-host routing variant.
- **TLS terminated in front of the cluster** (cloud load balancer, Traefik's default certificate or ACME resolver on the entrypoint): leave both `ingress.certificate.*` values empty. Keep `https://` in `urls.*.public`; Hub and Keycloak trust the `X-Forwarded-*` headers the controller sets.

With a certificate attached, Traefik serves the routes on its TLS entrypoint only (`websecure`, port 443) and answers 404 on port 80. An HTTP→HTTPS redirect is an entrypoint setting, not part of the chart — on K3s, for example, `--entrypoints.web.http.redirections.entryPoint.to=websecure` in the Traefik HelmChartConfig.

## Operating

**Upgrade** — back up the database first, then:

```bash
helm upgrade hub oci://ghcr.io/cryptomator/charts/cryptomator-hub --version <new version> \
  --namespace cryptomator --reuse-values
```

Hub applies its schema migrations at start; generated passwords are re-read from the existing Secrets, so they stay stable across upgrades.

**Backup** — everything lives in the PostgreSQL volume (`data-hub-pg-0`). Snapshot it with your storage provider, or dump both databases logically:

```bash
kubectl exec -n cryptomator hub-pg-0 -- pg_dumpall -U postgres > hub-backup.sql
```

**Sizing** — the defaults target a small installation: Hub 64Mi (native binary), Keycloak 512Mi requested / 1Gi limit, PostgreSQL 256Mi limit, 10Gi storage. Raise `keycloak.resources.limits.memory` for larger user bases (Keycloak's heap is 70% of its limit; see Keycloak's [sizing guide](https://www.keycloak.org/high-availability/concepts-memory-and-cpu-sizing)) and `postgres.storage.size` / `postgres.storage.storageClassName` as needed. Storage size cannot be changed on an existing StatefulSet volume through Helm; resize the PVC directly if your StorageClass allows expansion.

**Telemetry** — Hub can push metrics, traces and logs to an OpenTelemetry collector: `hub.metrics.enabled=true`, `hub.metrics.endpoint=https://otel-collector:4318`, optionally `hub.metrics.otlp.username` / `.password` for basic auth. Off by default.

**Existing infrastructure** — to reuse a Keycloak you already operate, follow [`../existing-keycloak/`](../existing-keycloak/README.md). To reuse an existing PostgreSQL server, set `postgres.enabled=false` and provide `hub.database.jdbcUrl` / `.username` / `.password` (plus `keycloak.database.*` for the bundled Keycloak's own database).

**Uninstall** — `helm uninstall hub -n cryptomator` removes the workloads and Secrets but keeps the PVC `data-hub-pg-0`; delete it explicitly if you want the data gone.

## Rancher

The chart ships a `questions.yaml`, so Rancher renders a guided form instead of a raw YAML editor. Add `oci://ghcr.io/cryptomator/charts` as a repository once (*Apps → Repositories → Create*; OCI repositories require Rancher 2.9+), then install *Cryptomator Hub* from *Apps → Charts*. The form asks for the two URLs, the ingress controller, an optional certificate and the admin passwords (blank = generated); untick *Deploy bundled PostgreSQL* / *Deploy bundled Keycloak* to connect to existing services. Everything else is available in the *Edit YAML* view. Generated passwords appear under *Storage → Secrets* (`hub-secrets-hub`, `hub-secrets-kc`, `hub-secrets-pg`).

## Things not to do in production

- `secrets.keepOnUninstall=true` — leaves passwords behind after `helm uninstall`.
- `hub.admin.passwordTemporary=false` together with a fixed `hub.admin.password` — the initial admin password should be changed on first login.
- Plain `http://` URLs — Hub's client-side crypto requires a secure browser context; only `localhost` is exempt.
